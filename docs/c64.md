# Zielplattform: Commodore 64

> **Stand 0.1:** geplant (Meilensteine 0.3, 0.5, 0.6). Dieses Dokument legt fest, was `m6510::C64` und `m6510::Kernal`
> nachbilden sollen, und sammelt die Fakten dafür. Adressen und Tabellen werden bei der Umsetzung gegen das
> *Commodore 64 Programmer's Reference Guide* und *Mapping the Commodore 64* geprüft.

Entsprechung in den Schwesterprojekten: Amstrad CPC (Z80) und Amiga 500 (MC68000). Wie dort gilt: der Prozessorkern bleibt
maschinenunabhängig, die Maschine hängt über Bus-Schnittstelle und Hooks an ([architecture.md](architecture.md)).

## Speicherlayout

| Bereich | Inhalt (Standardkonfiguration `$01 = $37`) |
|---|---|
| `$0000–$0001` | Prozessorport (Richtung, Daten) |
| `$0002–$00FF` | Zero Page; von BASIC und KERNAL stark belegt, frei z. B. `$FB–$FE` |
| `$0100–$01FF` | Stapel |
| `$0200–$03FF` | Arbeitsbereich von BASIC/KERNAL; RAM-Vektoren `$0314` (IRQ), `$0316` (BRK), `$0318` (NMI), `$031A–$0332` (KERNAL-I/O) |
| `$0400–$07FF` | Bildschirmspeicher (Standard), `$07F8–$07FF` Sprite-Zeiger |
| `$0800–$9FFF` | BASIC-Programmspeicher (erste Zeile bei `$0801`) |
| `$A000–$BFFF` | BASIC-ROM (8 KiB) oder RAM |
| `$C000–$CFFF` | RAM |
| `$D000–$DFFF` | I/O, Zeichensatz-ROM oder RAM |
| `$E000–$FFFF` | KERNAL-ROM (8 KiB) oder RAM |

I/O-Bereich (wenn eingeblendet):

| Bereich | Baustein | Bemerkung |
|---|---|---|
| `$D000–$D3FF` | VIC-II | 47 Register, alle 64 Byte gespiegelt |
| `$D400–$D7FF` | SID | 29 Register, alle 32 Byte gespiegelt; `$D419–$D41C` lesbar |
| `$D800–$DBFF` | Farb-RAM | 1000 Halbbytes (4 Bit; obere Bits lesen sich unbestimmt) |
| `$DC00–$DCFF` | CIA 1 | Tastatur, Joysticks, Timer → IRQ |
| `$DD00–$DDFF` | CIA 2 | VIC-Bank (Bits 0–1 von `$DD00`, invertiert), serieller Bus, Timer → NMI |
| `$DE00–$DFFF` | I/O 1 / I/O 2 | Cartridge-Erweiterungen |

## Speicherkonfiguration (`$01`)

Ohne Cartridge bestimmen die Bits 0–2 von `$01` (`LORAM`, `HIRAM`, `CHAREN`), was der Prozessor sieht:

| `$01` & 7 | `$A000–$BFFF` | `$D000–$DFFF` | `$E000–$FFFF` |
|---|---|---|---|
| `0`, `4` | RAM | RAM | RAM |
| `1` | RAM | Zeichensatz-ROM | RAM |
| `2` | RAM | Zeichensatz-ROM | KERNAL |
| `3` | BASIC | Zeichensatz-ROM | KERNAL |
| `5` | RAM | I/O | RAM |
| `6` | RAM | I/O | KERNAL |
| `7` | BASIC | I/O | KERNAL |

- **Schreiben** geht immer ins RAM – auch unter eingeblendetem ROM. Nur bei eingeblendetem I/O treffen Schreibzugriffe die
  Bausteine.
- Cartridges ändern die Karte über die Leitungen `EXROM`/`GAME` (8K: ROML `$8000–$9FFF`; 16K: zusätzlich ROMH `$A000–$BFFF`;
  Ultimax: ROMH bei `$E000`, viel Speicher unbelegt). Umsetzung mit CRT-Unterstützung (Meilenstein 0.6).
- Die **VIC-II-Sicht** ist eine andere: Der VIC sieht immer RAM aus einer 16-KiB-Bank (`$DD00`), in den Bänken 0 und 2
  zusätzlich das Zeichensatz-ROM bei `$1000–$1FFF` bzw. `$9000–$9FFF`, und das Farb-RAM direkt. Der Video-Renderer
  benutzt diese Sicht.

## Geräte: Register mit Schreibprotokoll

Wie beim Amiga-500-Profil des MC68000-Projekts gibt es **keine Gerätemodelle**, sondern Register als Speicher:

- Jeder Schreibzugriff auf VIC-II, SID, CIA 1/2, I/O 1/2 kommt ins **Schreibprotokoll** (`io`): Adresse, Wert, PC des
  schreibenden Befehls, Registername (z. B. `EXTCOL` für `$D020`; Namensquelle siehe
  [offene Fragen](roadmap.md#offene-fragen)), Spiegeladressen werden auf das Grundregister abgebildet.
- Lesen liefert den zuletzt geschriebenen Wert, mit Ausnahmen, die Programme sonst hängen lassen würden:
  - **Rasterzähler** `$D012` (und Bit 7 von `$D011`) rückt bei jedem Lesen vor (PAL: 312 Zeilen), damit Warteschleifen auf
    eine Rasterzeile enden – Vorbild ist der Strahlzähler (`VHPOSR`) im MC68000-Projekt.
  - **CIA-Timer** zählen beim Lesen weiter (einfaches Modell), Interrupt-Steuerregister liest sich und löscht sich.
  - **Tastatur/Joystick** (`$DC00/$DC01`): keine Taste gedrückt (`$FF`), sofern die KERNAL-Emulation keine Eingabe vorgibt.
  - `$D019`, `$DC0D`, `$DD0D` (Interrupt-Flags): löschen sich beim Quittieren wie auf der Hardware.
- **Interrupts** kommen nicht von selbst; der Agent oder Monitor fordert sie an (`interrupt irq|nmi`). Eine Option „IRQ alle
  n Zyklen“ (50-Hz-Takt) ist vorgesehen, damit IRQ-gesteuerte Programme (Musik, Raster-Splits) laufen.

### Emulierte KERNAL-Aufrufe (`m6510::Kernal`)

Vorbild: die OS-Emulation (`m68k::AmigaOs`) des MC68000-Projekts. Ohne geladenes KERNAL-ROM wird der Bereich `$E000–$FFFF`
mit Stubs belegt; erreicht der PC einen Eintrag der Sprungtabelle, führt ein **Ausführungs-Hook** die C++-Nachbildung aus
und kehrt wie mit `RTS` zurück. Auch die RAM-Vektoren (`$0314` …) und die Hardware-Vektoren `$FFFA–$FFFF` werden sinnvoll
belegt, sodass ein Programm, das eigene IRQ-Routinen einhängt, funktioniert.

| Gruppe | Verhalten |
|---|---|
| `CHROUT` | Zeichen in die **Konsole** (PETSCII → Text) **und** in den Bildschirmspeicher (Cursor, Steuerzeichen für Farbe, `CLR`, `HOME`, Zeilenumbruch, Scrollen) |
| `CHRIN`, `GETIN`, `SCNKEY`, `STOP` | Eingabe aus einem vorgegebenen Tastenpuffer (`keys`), sonst „keine Taste“ |
| `PLOT`, `SCREEN`, `IOBASE`, `MEMTOP`, `MEMBOT`, `RDTIM`, `SETTIM`, `UDTIM`, `READST`, `SETMSG` | nachgebildet (Jiffy-Uhr zählt mit den angeforderten IRQs bzw. Zyklen) |
| `SETLFS`, `SETNAM`, `OPEN`, `CLOSE`, `CHKIN`, `CHKOUT`, `CLRCHN`, `CLALL`, `LOAD`, `SAVE` | Dateien aus einem angehängten **D64/T64** oder Verzeichnis (nur mit `--allow-files`), Gerät 8; `LOAD` mit Sekundäradresse 0/1; `SAVE` in ein Speicherabbild |
| `CINT`, `IOINIT`, `RAMTAS`, `RESTOR`, `VECTOR` | setzen den Zustand wie nach dem Einschalten |
| serieller Bus (`LISTEN`, `TALK`, `ACPTR`, …) | protokolliert, Rückgabe „Gerät nicht vorhanden“ |

**Alles, was nicht nachgebildet ist, wird protokolliert** (`kernalcalls`: Name, Aufrufer, Register vorher/nachher) und kehrt
mit `C` = 0 zurück – kein Blockieren, keine Abstürze. Jeder Aufruf meldet, ob er nachgebildet war.

**BASIC** wird nicht emuliert. Ein Programm mit BASIC-Starter (`10 SYS 2061`) wird erkannt und direkt an der `SYS`-Adresse
gestartet (wie `RUN`); andere BASIC-Programme werden detokenisiert angezeigt, aber nicht ausgeführt.

### Echte ROMs

BASIC (`$A000`, 8 KiB), KERNAL (`$E000`, 8 KiB) und Zeichensatz (4 KiB) können als eigene Kopie geladen werden
(`load_rom`, Monitor `rom`). Sie sind urheberrechtlich geschützt und kommen **nie** ins Repository (`.gitignore`). Mit
echtem KERNAL läuft der Kaltstart bis `READY.`; das ist ein lokaler Test (`C64_ROMS=<verzeichnis>`), siehe
[offene Fragen](roadmap.md#offene-fragen) zur CI.

Für Screenshots ohne Zeichensatz-ROM wird ein **eigener** Ersatzzeichensatz mitgeliefert (selbst gezeichnet, nicht aus dem
Original abgeleitet), damit Texte lesbar sind.

## Video: der Bildschirm als Bild

Wie beim CPC im Z80-Projekt soll ein Modell mit Bildverständnis den Bildschirm sehen. Gerendert wird **aus dem
Speicherzustand** (Registerstand am Ende, VIC-Sicht des Speichers), nicht zeilengenau:

| Modus | Register | Stand |
|---|---|---|
| Standard-Text (40×25, 16 Farben) | `$D011` Bit 5 = 0, `$D016` Bit 4 = 0 | Meilenstein 0.5 |
| Multicolor-Text | `$D016` Bit 4 = 1 | 0.5 |
| Extended Background Color | `$D011` Bit 6 = 1 | 0.5 |
| Hires-Bitmap (320×200) | `$D011` Bit 5 = 1 | 0.5 |
| Multicolor-Bitmap (160×200) | Bit 5 + Multicolor | 0.5 |
| Sprites (8, Hires/Multicolor, Vergrößerung) | `$D000–$D02E` | Idee |
| Rahmen, `$D020/$D021`, Scroll-Register, 38/24-Spalten-Modus | | 0.5 |
| Raster-Splits (Registerstand pro Zeile aus dem Schreibprotokoll) | | Idee |

Ausgabe: PNG (eigener Encoder ohne externe Bibliothek, wie im Z80-Projekt), Ausschnitt und Vergrößerung wählbar, dazu der
**Textinhalt** des Bildschirms als Zeichenkette (Bildschirmcodes → Text), damit auch ein Modell ohne Bildverständnis lesen
kann. Palette: siehe [offene Fragen](roadmap.md#offene-fragen).

## Dateiformate

PRG, P00, T64, D64, CRT – siehe [formats.md](formats.md). Ein Programm wird standardmäßig an seiner Ladeadresse abgelegt;
liegt sie bei `$0801` und beginnt mit einem BASIC-Starter, ist der Einsprung die `SYS`-Adresse.

## Umsetzung: `m6510::C64` (geplant)

- Speicher: 64 KiB RAM (`Memory`), ROM-Abbilder (optional), Farb-RAM (1 KiB × 4 Bit), Registerbank für die Bausteine
- Bus: `read`/`write` nach der aktuellen Konfiguration (`$01`, `EXROM`/`GAME`), Spiegelungen, Schreibprotokoll
- Zustand für Checkpoints und Snapshots: RAM, Farb-RAM, Register, Prozessorport, Rasterzähler, KERNAL-Emulationszustand
  (Cursor, Dateien, Tastenpuffer)
- `machine c64` in Sitzung und Monitor; `generic` bleibt: 64 KiB RAM überall, kein Prozessorport-Banking
